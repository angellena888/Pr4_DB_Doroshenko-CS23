# Контекстна діаграма (з ЛР3)

## Аналіз контекстної діаграми
Контекстна діаграма представляє систему як один процес «Продаж авіаквитків» та визначає основні зовнішні сутності: **Клієнт**, **База рейсів**, **Тарифний модуль**, **База літаків**.  
Вона показує, які дані надходять у систему (клієнтські критерії пошуку), і які дані система повертає (ціни, доступні рейси, квиток). Діаграма демонструє межі системи та основні інформаційні взаємозв’язки.

# Модель IDEF3

##  Аналіз IDEF3
IDEF3-модель описує сценарій «Обробка замовлення авіаквитка».  

1. **Початок процесу:** клієнт надсилає запит.  
2. **Розгалуження J1:** система виконує паралельно  
   - пошук рейсів,  
   - обчислення вартості,  
   - перевірку наявності місць.  
3. **Синхронізація J2:** усі результати об'єднуються.  
4. **Формування квитка:** генерується електронний квиток і повертається клієнту.

Модель демонструє реалізацію паралельних бізнес-операцій та логіку системи бронювання.

#  Модель DFD


## Аналіз DFD
DFD-модель описує рух даних у системі продажу авіаквитків:

- **P1:** Отримання запиту → формування запиту до бази.  
- **P2:** Пошук рейсів → джерело: база рейсів.  
- **P3:** Розрахунок вартості → джерела: тарифи, класи, типи літаків.  
- **P4:** Формування квитка → запис до системи та результат для клієнта.

DFD показує логіку обробки даних, інформаційні потоки та структуру взаємодії з базами.

# Висновки
Побудовані моделі IDEF0, IDEF3 та DFD допомогли зрозуміти, як працює процес продажу авіаквитків: які дані використовуються, які кроки виконує система та що отримує користувач. Таке моделювання дозволяє виявити помилки, оптимізувати процеси й забезпечити зрозумілу структуру для аналітиків, розробників та замовника.
